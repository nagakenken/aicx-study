## データ構造

`sections_data.json` と同じトップレベル構造（32 Section の配列）なので、既存の読み込み処理を流用できる。

```json
[
  {
    "ch": 1, "s": 1, "title": "生成AIの基礎",
    "quizzes": [
      {
        "question": "設問文（シナリオを含む場合は \\n 区切りで X/Y/Z 等の列挙あり）",
        "choices": {"A": "...", "B": "...", "C": "...", "D": "..."},
        "correct_letter": "A",
        "answer": "A",
        "explanation": "正解：A｜正答の根拠。B/C/D それぞれの誤りの理由。",
        "q_type": "業務シナリオ適用判断",
        "difficulty": "標準"
      }
    ]
  }
]
```

- `question / choices / correct_letter / answer / explanation` は既存クイズと同一仕様（answer は correct_letter の複製）
- **追加フィールド**（アプリ側は無視しても動く）:
  - `q_type`: シラバス「出題で想定する問いの型」6類型のいずれか
    （定義・構成要素の理解 / 業務シナリオ適用判断 / 前提整理 / ワークフロー設計妥当性 / 組織導入・チェンジマネジメント判断 / 5Dモデル進め方判断）
  - `difficulty`: 基礎 / 標準 / 応用

- 選択肢の長さバイアス補正済み（正答長/誤答平均の最大1.7倍、中央値1.39倍）。ただし「正答が4択中最長」の問題が84%残っており、気にする場合は将来の改善余地

## アプリ実装への提案

1. **模擬試験モード**: 128問からランダム50問（章別比率 Ch1:12 / Ch2:5 / Ch3:11 / Ch4:6 / Ch5:8 / Ch6:8 ≒ 実試験の範囲配分想定）を出題 → 採点 → 章別・類型別の正答率表示
2. **弱点演習モード**: `q_type` / `ch` でフィルタして出題
3. 既存のセクション別クイズ（sections_data.json）とはデータを分離したまま運用する（本ファイルは既存データに一切手を入れていない）

## 再生成・追加生成の方法

- 本文抽出: `python mock_exam/extract_sections.py`（圧縮PDFから32 Sectionのテキストを `mock_exam/source/` に出力）
- 出題設計: `mock_exam/design_matrix.md`（類型配分・生成原則・既存問題ネガティブリスト）
- QA・統合: `python mock_exam/qa_mock_exam.py --merge`
